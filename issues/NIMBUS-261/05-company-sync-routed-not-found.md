# 05: Company sync routed, NOK, and the not-found record
**App:** backend · **Layer:** L0 model + migration, L3 step, L4 workflow · **Depends on:** 02

**Goal:** The company sync reads the BC customer in the company's environment, resolves a blank currency to that environment's local currency, records "customer not found" and clears it on success, for every trigger.
**Files / areas:** `modules/company/models/company.ts`, `modules/company/migrations/` (generated), `types/company/{module,query,http}.ts`, `workflows/company/steps/prepare-company-bc-sync.ts`, `workflows/company/workflows/sync-company-from-business-central.ts`, `workflows/business-central-order/utils/resolve-bc-currency-override.ts`.
**Seam contracts:**
- Columns: `business_central_not_found_at` `dateTime` nullable; `business_central_not_found_environment` enum `["DK","NO"]` nullable; `business_central_not_found_customer_number` text nullable.
- `PreparedCompanyBcSync` gains an internal `not_found` outcome carrying an update with exactly `id` and the three columns; the `ready` update also sets the three columns to null.
- `SyncCompanyFromBusinessCentralResult.status` stays `"updated" | "skipped" | "failed"`; `not_found` maps to `skipped`.
- `resolveCurrencyCode` takes the environment; `resolveBcCurrencyOverride` passes `"DK"`.
- The task 02 account step selects the three columns for its `notFound` output.
**Test intent:**
- Unit: blank currency → `NOK` for NO, `DKK` for DK, configured overrides respected; a set currency is kept.
- Integration (`company-sync.spec.ts`): country `NO` → `getCustomer("NO", number)`; DK/blank → `"DK"`; BC returns `null` → outcome `skipped`, the three columns set (environment and number match), BC-managed fields and `business_central_synced_at` unchanged; a later found sync clears all three; no customer number → nothing written; BC error → `failed`, an existing record unchanged. One case per trigger input shape (customer, company id).
- Contract (`companies.spec.ts`): Admin sync route still returns `{ status }` with the three values; `GET /store/companies/:id` returns none of the new fields.
**Done when:** the generated migration adds only the three columns (read it), and typecheck shows no new errors.
**Verify after deploy:** `company.business_central_not_found_at`, `_environment`, `_customer_number` for one test company with a deliberately wrong number after an Admin sync; then cleared after correcting the number and syncing.
**Also update:** `integration-tests/http/customers/company-sync.spec.ts:457,566` and `integration-tests/http/companies/companies.spec.ts:919` (`getCustomer` now gets the environment first); `src/workflows/business-central-order/__tests__/resolve-bc-currency-override.unit.spec.ts`; `ai/architecture/decisions.md` row "BC company sync" (outcomes now include the not-found record, environment-dependent LCY); `docs/architecture/business-central-company-sync.md` left to `documentation-writer`.

## Deviations

- **Changed task 02's seam (approved by the dispatcher): `BusinessCentralNotFoundRecord.at` is an ISO 8601 `string`, not a `Date`. Tasks 06 and 07 must use the string.** Why: Medusa serialises step output and the workflow result, so `resolveBusinessCentralAccountWorkflow` can never return a `Date`. A throwaway probe showed a `new Date(...)` built inside `transform` comes out of `run()` with `typeof` `"string"`. The integration run failed the two not-found cases on exactly this. A declared type must match the runtime value (`medusa-boundary.md`, Types). `load-business-central-account-company.ts` now normalises the column to an ISO string (`BusinessCentralAccountCompanyRow.business_central_not_found_at: string | null`), and the two `business-central-account.spec.ts` cases assert `at.toISOString()`.
- **Migration generated against a throwaway database.** The first attempt failed (no Postgres on `localhost:5432`). The rerun of `medusa db:generate company` used a scratch Postgres the dispatcher started (`localhost:55433`, empty database; `.env` untouched, settings overridden in the shell; `loadEnv` keeps shell values, checked). It produced `Migration20261027225750.ts` and a `.snapshot-company.json` change, read in full: three `add column if not exists` (timestamptz null; text with `check (… in ('DK', 'NO'))` null; text null), the matching drops in `down`, and three new column entries in the snapshot. No other drift. Not hand-edited. `db:migrate` was not run against the dev database.
- `resolveCurrencyCode` moved from the step file to `workflows/company/utils/resolve-currency-code.ts` with the signature `resolveCurrencyCode(environment, bcCurrencyCode)` (environment first, as in the BC module). It delegates the fallback to `getBusinessCentralLocalCurrency(environment)`, so the local-currency rule has one home. Why: `business-central-order/utils/resolve-bc-currency-override.ts` imported it from a step (`bound-helper-pure`); it now imports a util. The comment in `modules/business-central/service.ts` that points at it was updated.
- Added `src/workflows/company/__tests__/sync-company-from-business-central.unit.spec.ts`: runs the real workflow and steps with Query, the company module and the BC module replaced, one block per trigger shape. Why: the integration cases cannot run here; this proves routing, the not-found update's exact keys (security matrix "Not-found record holds no personal data") and the clearing locally. It fails 8 of 18 cases against the previous step and workflow (checked with `git stash`).
- Types: only `types/company/module.ts` changed. `QueryCompany` derives from `ModuleCompany`; `http.ts` needed nothing (`AdminSyncCompanyBusinessCentralResponse` keeps its three values; store response types were already `QueryCompany`).
- Extra contract case in `companies.spec.ts`: the Admin sync route reads a `NO` company in `NO`. Extra integration cases in `business-central-account.spec.ts` for the account workflow's `notFound` mapping (both trigger shapes), for the seam item "the task 02 account step selects the three columns".
- The "Also update" lines `company-sync.spec.ts:457,566` and `companies.spec.ts:919` stay `("DK", number)`: those companies have country `DK`, which routes to DK. The routed cases are new tests beside them.
- The not-found log line changed from "sync skipped: no matching customer" to "no matching customer … (environment X)"; the failed line also names the environment. Both log company id and environment only.
- Locally regenerated the gitignored `.medusa/types` (the type generation `medusa build` runs, without a database) so typecheck sees the new columns; the typecheck result depends on it. Anyone else gets it from `medusa develop` or `medusa build`.
